# xera v0.7 Implementation Plan — Index

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship xera v0.7 — `@xera-ai/http` adapter sibling of `@xera-ai/web`, supporting API-only and mixed projects, with pre-authentication per role, three new classifier buckets (`CONTRACT_DRIFT`, `RATE_LIMITED`, `AUTH_EXPIRED`), and web prompt awareness of `page.request`.

**Architecture:** New package `@xera-ai/http` mirrors `@xera-ai/web`'s `TestAdapter` shape but runs Playwright's `APIRequestContext` standalone (no browser). Pre-auth runs via `npx xera-internal auth-setup` and writes encrypted per-role token files to `.xera/.auth/http/<role>.json` (symmetric with web's storageState pattern). Skill dispatch chooses prompt + executor by `meta.json.adapter`. Web prompt is renamed and gains a section teaching the LLM to use `request` for backend assertions. `scrub-rules` relocates from web to core so both adapters share it.

**Tech Stack:** Node, TypeScript 5.x strict, `@playwright/test` (request context only for http), `@apidevtools/json-schema-ref-parser`, zod, `npx vitest run`, AES-256-GCM (existing util in core).

**Spec:** [docs/superpowers/specs/2026-05-16-xera-v07-http-adapter-design.md](../specs/2026-05-16-xera-v07-http-adapter-design.md)

## Execution Notes

- Each task ends with `git commit`; commits within a task should also be frequent if multiple files change.
- Node version: same as v0.6 (`>=22.0.0` per root `engines`).
- Test runner: `npx vitest run` everywhere. Mirror src path in test path.
- TypeScript: `strict: true`, `noUncheckedIndexedAccess: true`, `exactOptionalPropertyTypes: true` (per repo defaults). When in doubt, use conditional object construction (see CLAUDE.md reflexes).
- Tests do NOT require a build first — `source` exports condition resolves workspace packages from `./src/`.
- Commit message style: `<scope>: <summary>` where scope ∈ {`core`, `web`, `http`, `cli`, `skills`, `prompts`, `fixtures`, `docs`, `chore`, `release`}.
- **Never include the model identifier** in commits, PR titles/bodies, code comments, or any artifact pushed to the repo.

## Definition of Done for v0.7

A maintainer can:

1. `npm install && npm run typecheck && npm run lint && npx vitest run` → all green.
2. `cd /tmp && rm -rf xera-api-tryout && mkdir xera-api-tryout && cd xera-api-tryout && npx @xera-ai/cli init --yes --shape api` → scaffolds api-only project. No Chromium install.
3. Set `USER_BEARER_TOKEN` in `.env.local`. Run `npx xera-internal auth-setup --role user`. Confirm `.xera/.auth/http/user.json` exists, encrypted, `xera doctor` ✓.
4. Open Claude Code in that directory. Run `/xera-run SAMPLE-HTTP-001`. The sample's `webServer` (bundled mock) starts, test runs, posts to mock-jira.
5. Repeat with `--shape mixed`: ticket whose AC mentions backend state assertions generates a script using both `page.click` and `request.get`.
6. Seed an expired JWT into a role's auth file. Re-run → classifier outputs `AUTH_EXPIRED` with the suggested re-auth command.
7. Existing v0.6 web-only projects continue to work after `npm install @xera-ai/core@^0.5.0` without changing their `xera.config.ts`; their `.xera/.auth/<role>.json` files are read via the v0.7 fallback path (auto-migration on next `init --upgrade`).

All seven must work without source-code inspection.
