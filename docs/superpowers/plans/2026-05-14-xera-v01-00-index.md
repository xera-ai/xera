# xera v0.1 Implementation Plan — Index

> **Status:** ✅ Completed 2026-05-14. All 74 tasks across the 5 sub-plans are implemented and shipped. v0.1.0 is live on npm and GitHub. See [POSTMORTEM.md](POSTMORTEM.md) for bugs the plan itself contained and patches landed after launch (rounds 1–3).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship xera v0.1 — an AI-native test framework for Web E2E testing, invoked via Claude Code skills, with Jira integration and AI-driven failure diagnosis.

**Architecture:** A Bun-based TypeScript monorepo. Public `bunx xera` CLI handles only `init` and `doctor`. End users do everything else via Claude Code skills (`.md` files), which invoke deterministic helpers through `bun run xera:*` scripts → `xera-internal` binary in `@xera-ai/core`. The Playwright adapter lives in `@xera-ai/web`. AI work happens in the QA's Claude Code session; the framework provides prompts and orchestration.

**Tech Stack:** Bun, TypeScript 5.x, Playwright 1.x, zod, vitest (or `bun test`), commander/cac, @cucumber/gherkin parser, AES-256-GCM (node:crypto), Atlassian MCP, Next.js (fixture app only).

**Spec:** [docs/superpowers/specs/2026-05-14-xera-core-web-design.md](../specs/2026-05-14-xera-core-web-design.md)

## Execution Notes

- Each phase ends with `git commit`; commits within a phase should also be frequent.
- Bun version: `>=1.1.0`. Pin in `package.json` `engines`.
- Node compatibility: target only Bun runtime. We do not support Node directly.
- Test runner: use `bun test` everywhere. Snapshot files: `__snapshots__/`.
- TypeScript: `strict: true` and `noUncheckedIndexedAccess: true` enabled root-wide.
- Linter: biome (single binary, no ecosystem of plugins) — `bunx biome check`.
- All `bun run xera:*` scripts use `bun run --bun` to force the Bun runtime.
- Commit message style: `<scope>: <summary>` where scope is the package name (`core`, `web`, `cli`, `skills`, `prompts`, `fixtures`, `docs`). Example: `core: add zod config schema`.

## Definition of Done for v0.1

A fresh QA, on a fresh machine with Bun + Claude Code installed, can:

1. `bunx xera init` in an empty directory and answer the prompts.
2. Open Claude Code and run `/xera-run SAMPLE-001` → see green.
3. Run `/xera-run <their-jira-key>` against their own staging app → see real Gherkin, real Playwright spec, real test run, real classification, real Jira comment.

All three must work without the QA reading source code or editing internal files.
